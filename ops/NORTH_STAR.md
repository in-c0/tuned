# Tuned — North Star

Last updated: 2026-08-06 (loop bootstrap; update whenever doctrine, hypothesis, or funnel materially changes)

## Doctrine (non-negotiable)

Humans contribute **attention, not content**. Tuned lets people follow human and agent attention with **explicit provenance**. Notes are never required. Do not turn Tuned into a generic summarizer, content generator, enterprise agent-observability dashboard, or unrelated product.

Provenance states must never be blurred:

1. **Observed by agent** — the agent encountered it.
2. **Selected by agent** — the agent judged it relevant.
3. **Opened by human** — the owner inspected it.
4. **Starred by human** — the owner deliberately endorsed it.
5. **Shared by human** — the owner made it part of their public attention.

"via @agent" attribution is foundational, not decorative.

## Commercial hypothesis (owner brief, 2026-08-06 — see BRIEF-2026-08-06.md for verbatim)

The urgent problem is not "people need to follow agents." It is **"agents can consume vastly more information than humans can review."** Following agents is the network layer built on top of that.

Product sequence:

1. **Single-player wedge (now):** the daily desk for delegated attention — a compact morning review queue of what your agents inspected, selected, and why; star/skip/hide/redirect teaches the agent your taste. Useful to one person alone; no social cold-start dependency.
2. **Multiplayer:** follow a person's curated attention, or one of their agents, or both; clone public agent remits; convergence across trusted agents; shared team feeds.
3. **Attention network:** the public provenance layer between machine-scale perception and human-scale attention.

Positioning: lead with **"Wake up to the few things worth your attention."** The social vision ("follow the attention of people and agents you trust") comes second.

Monetization frame: Free (follow public feeds, open RSS) / Pro ~$17/mo (personal agents, private feeds, morning desk, history, preference learning) / Team (shared agents, coverage maps, review assignments) / Agent creators (identity, analytics, distribution, optional paid feeds later).

## Constraints

- Deploy pipeline: Cloudflare Workers Builds (Git-connected, branch `master`, build `npm ci && npm run check`, deploy `npx wrangler deploy`). **Connected by the owner 2026-08-06 (evening)** — pushes to master now deploy after gates pass.
- **2026-08-06 (run 1): the build gate itself was broken and is now fixed.** On a fresh clone `npm ci && npm run check` exited 2 (TS2688 — `worker-configuration.d.ts` is generated by `wrangler types` and gitignored, but `tsconfig.json` requires it). Connecting the Git integration alone would therefore have produced a permanently failing build and zero deploys. `check` now generates the types first, and `.github/workflows/check.yml` runs the same command on every PR so this cannot regress silently.
- **Executor read path, corrected 2026-08-06 (runs 2 and 3):** the routine environment **still cannot reach `justtuned.com`** — `403` on CONNECT at the egress proxy, re-tested every run; `example.com` is refused identically, so this is a general allowlist state, not a justtuned-specific rule. `*.workers.dev` is blocked too, so Cloudflare preview URLs are not a way around it. The widening recorded on 2026-08-06 evening is **not in effect for this session** — treat this as the standing condition, not a pending confirmation. `.github/workflows/verify-production.yml` runs the post-deploy checks from GitHub's network instead and publishes a result the executor reads via the Actions API, and `.github/workflows/metrics-snapshot.yml` commits the aggregate JSON into `ops/metrics/` where the executor reads it as a file — so this is a standing limitation rather than a stop condition. `wrangler`/D1 remains unauthenticated by design, so D1-sourced metrics still need an owner relay or in-app instrumentation whose output reaches the repo.
- **Executor cadence is bounded — do not re-open it (run 3).** The scheduled routine runs 3×/day (08:00/14:00/20:00 Sydney). `.github/workflows/claude-continuation.yml` can also fire a session on a push to `master`, but **only when the head commit message carries the explicit opt-in marker**; it defaults closed. Without that guard the loop self-sustained — the executor ships by pushing to master, so every push fired the next session — and on 2026-08-06 it produced three fires in six minutes and two sessions deploying to production concurrently. Adding the marker to a commit is a deliberate act for genuinely staged multi-step work; loosening the condition itself re-creates unbounded inference spend and unattended deploys.
- **Deploy verification proves version identity (run 6, 2026-08-07).** `scripts/build-info.mjs` stamps the build commit into the Worker during `npm run check`, `GET /api/version` reports it, and `verify-production.yml` polls until that value equals the pushed SHA before running any health check — failing closed, with the health steps skipped, if it never matches within 8 minutes. This replaced a gate that inferred freshness from a fixed sleep plus "does `/api/metrics` exist", which stopped discriminating the moment that route shipped in every build. Do not reintroduce a timing-based freshness check: an unverifiable deploy must be treated as a failed deploy, because a green health result on an unknown version is worse than no result.
- **Claim the directive before working it (run 6, 2026-08-07).** Two executor sessions are fired by two independent triggers — the 3×/day schedule and `claude-continuation.yml`'s `issue_comment` path — and on 2026-08-07 they implemented the same directive twice, then the same follow-up fix twice (#7/#8, #9/#10). Nothing in issue #1 distinguishes "unclaimed" from "already being worked". So: after reading issue #1 and **before** selecting an action, re-read the latest comments; if a comment carrying `<!-- tuned-run-claim -->` is newer than the latest reviewer directive, that directive is taken — choose a disjoint action or stop and say why. If none exists, post one (marker, UTC time, directive claimed) and proceed. When two PRs do turn out to duplicate, resolve by **earliest opened wins** — a symmetric rule both sessions can apply without talking, unlike "defer to the other", which ships nothing.
